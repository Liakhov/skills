# Reframe

The user did not understand your previous response. Explain it again, more clearly and with fewer words. Do not repeat the same wording.

## Instructions

1. Briefly remind the user of the goal and where the discussion stands.
2. State the main point first. Explain why it matters only if needed.
3. Make the next step clear, if there is one.

## Writing rules

- Follow ASD-STE100 Simplified Technical English principles: short, direct sentences, active voice, common words, and one main idea per sentence.
- Keep exact technical names (code, files, APIs, commands). Explain unfamiliar terms simply.
- **Keep the answer short by default: aim for 3–5 sentences and about 100 words or less.** Use more only when essential for understanding.
- Avoid long introductions, repeated points, unnecessary examples, and exhaustive lists.
- Preserve important facts, limitations, and uncertainty. Correct any earlier mistake explicitly.
- Do not start new work or change files just to explain the previous response.

The goal is a quick explanation, not a full rewrite or a tutorial.
